## Die Kurzfassung

Moodle 5.0 erschien am 14. April 2025 und hat bereits das End of Life erreicht. Es war nie eine Long-Term-Support-Version, weshalb die Community schnell weiterging. Das bedeutet nicht, dass es irrelevant ist. Wenn Sie von Moodle 4.x auf 5.2 oder neuer wechseln, führt Ihr Upgrade-Pfad durch die Anforderungen, die Moodle 5.0 festgeschrieben hat: PHP 8.2 als Mindestanforderung, erhöhte Datenbankuntergrenzen, Bootstrap 5 und die dauerhafte Entfernung von Atto, Oracle, Chat, Survey und MNet. Diese Änderungen verschwinden in späteren Versionen nicht. Sie begannen hier.

Diese Seite beschreibt, was sich in Moodle 5.0 tatsächlich geändert hat, was dauerhaft entfernt wurde und was Sie vor einem Upgrade prüfen müssen, das diese Version beinhaltet.

## Warum Moodle 5.0 relevant bleibt, auch wenn Sie es überspringen

Die Moodle-Versionsnummern folgen einem vorhersehbaren Muster: jede vierte Version ist eine Long-Term-Support-Version. Moodle 4.5 LTS ging Moodle 5.0 voraus, und Moodle 5.1 war der nächste LTS-Kandidat, auf den die meisten Installationen abzielten. Moodle 5.0 ist eine Standardversion, die nur bis zur nächsten Standardversion unterstützt wird, weshalb ihr EOL so schnell kam.

Die Anforderungsänderungen in Moodle 5.0 sind jedoch real und wirken fort. Wenn Ihre Installation noch PHP 8.1, MariaDB 10.6 oder MySQL 8.0 (vor 8.4) verwendet oder auf Oracle läuft, ist Moodle 5.0 die Version, ab der diese Konfigurationen nicht mehr funktionieren. Diese Grenze wird in Moodle 5.1 oder 5.2 nicht weicher.

## Serveranforderungen für Moodle 5.0

Dies sind Mindestwerte. Der Betrieb auf dem Minimum ist für Testserver akzeptabel; Produktion sollte auf dem neuesten stabilen Point Release der jeweiligen Komponente laufen.

| Anforderung | Moodle 5.0 Minimum | Hinweise |
| --- | --- | --- |
| Ausgangsversion | Moodle 4.2.3 oder neuer | Sprung von 4.1 oder älter nicht möglich |
| PHP | 8.2.0 | 8.3.x und 8.4.x ebenfalls unterstützt |
| PHP-Architektur | Nur 64-Bit | 32-Bit seit Moodle 4.1 gestrichen |
| PHP-Erweiterung | sodium | Pflicht, nicht optional |
| PHP-Einstellung | max_input_vars >= 5000 | Niedrigere Werte brechen Formularübertragungen |
| PostgreSQL | 14 | Erhöht von 13 |
| MySQL | 8.4 | Erhöht von 8.0 |
| MariaDB | 10.11.0 | Erhöht von 10.6 |
| Aurora MySQL | 8.0 | Versionierung wie MySQL, nicht Aurora-intern |
| Microsoft SQL Server | 2017 | Unverändert |
| Oracle | Entfernt | Ab Moodle 5.0 nicht mehr unterstützt |

Der Datenbankpräfix ist seit Moodle 4.3 auf 10 Zeichen begrenzt. Ist Ihr `$CFG->prefix` länger, scheitert das Upgrade bevor es beginnt.

## Was in Moodle 5.0 entfernt wurde

Dies ist die Liste, die Administratoren überrascht, die die Release Notes nicht lesen.

### Atto-Texteditor

MDL-83282 entfernte Atto dauerhaft. TinyMCE ist jetzt der einzige gebündelte Rich-Text-Editor. Wenn Plugins, Themes oder benutzerdefinierte Formulare Atto-spezifische APIs oder Templates referenzieren, werden sie nach dem Upgrade nicht mehr funktionieren.

TinyMCE erhielt in Moodle 5.0 zudem ein Zugänglichkeits-Plugin (MDL-84125), rollenbasiertes Deaktivieren von Plugins (MDL-84126) und eine verbesserte Medieneinbindung (MDL-78428).

### Oracle-Datenbank

MDL-83172 hat Oracle-Unterstützung vollständig entfernt. Wenn Ihre Institution Moodle auf Oracle betreibt, ist Moodle 5.0 eine harte Grenze. Es gibt keinen Migrationspfad innerhalb von Moodle selbst; Sie müssen Ihre Daten exportieren und vor dem Upgrade auf einem unterstützten Datenbankserver neu aufbauen. PostgreSQL ist die empfohlene Zieldatenbank für Installationen mit hohem Reporting-Volumen.

### Chat- und Survey-Aktivitäten

MDL-82457 hat das Chat-Modul und das Survey-Modul aus dem Moodle-Core entfernt. Installationen, die diese Aktivitäten nutzen, müssen prüfen, wer darauf angewiesen ist, bevor das Upgrade beginnt. Das Survey-Modul speicherte Antwortdaten, die nicht automatisch auf eine Alternative migriert werden.

### Authentifizierungs-Plugins

MDL-78778 entfernte das CAS-Authentifizierungs-Plugin (auth_cas). Installationen, die CAS für Single Sign-On nutzen, müssen vor dem Upgrade auf eine Alternative migrieren. SAML2, OAuth2 oder LDAP sind je nach Identity Provider die üblichen Alternativen. Einen Überblick über SSO-Optionen bietet [SSO-Optionen für Lernplattformen](/de/blog/sso-options-for-learning-platforms).

### MNet

MDL-84652 hat alle MNet-Plugins entfernt. MNet war Moodles eigenes Peer-to-Peer-Netzwerksystem. Die meisten Installationen hatten es bereits nicht mehr in Betrieb, aber wenn Ihre Installation aktive MNet-Verbindungen für Einschreibungen oder Authentifizierung nutzte, funktionieren diese nach dem Upgrade nicht mehr.

### Weitere Entfernungen

MDL-84265 hat SQLite-Unterstützung aus Moodles Datenbankschicht entfernt. MDL-83703 entfernte das ältere subplugins.php-Erkennungsformat. MDL-84107 entfernte das PHP-Machine-Learning-Backend. MDL-61232 hat admin/process_email.php abgekündigt. Diese Änderungen betreffen typische Produktionsinstallationen nicht, aber sie sind relevant, wenn Ihre Konfiguration darauf angewiesen war.

## Was in Moodle 5.0 neu ist

### Zentralisierte Kursübersichtsseite

Die sichtbarste Änderung für Studierende und Lehrende ist die neue Kursaktivitäts-Übersichtsseite (MDL-83871). Anstatt zur Indexseite jeder Aktivität zu navigieren, erhalten Nutzer eine einheitliche Ansicht aller Aktivitäten in einem Kurs. Sie verwendet On-Demand-Tabellen (MDL-83872), damit die Seite nicht alles auf einmal lädt, und zeigt eine Benachrichtigungszählung (MDL-84602), sodass Lehrende auf einen Blick sehen können, welche Aktivitäten Aufmerksamkeit erfordern.

### KI-Verbesserungen

Moodle 5.0 erweiterte das KI-Subsystem in vier Richtungen: ein neuer Ollama-Provider (MDL-83006) für lokale Sprachmodelle ohne externe API, Unterstützung für mehrere Provider-Instanzen (MDL-82977), modellspezifische Einstellungen (MDL-82980) mit Provider-Reihenfolge (MDL-83216) sowie Admin-Berichte zur KI-Nutzung und Richtlinienakzeptanz (MDL-83395, MDL-83396).

Der Ollama-Provider ist für Institutionen mit strengen Datenschutzanforderungen praktisch relevant. Für einen realistischen Überblick darüber, welche KI-Funktionen in einem LMS tatsächlich helfen, lesen Sie [KI in einem LMS: Was tatsächlich hilft](/de/blog/ai-in-an-lms-what-actually-helps).

### Open Badges 3.0

MDL-82905 und zugehörige Tickets aktualisierten Moodles Badge-System in Richtung der Open Badges 3.0-Spezifikation. Das Badge-Erstellungsformular wurde überarbeitet und vereinfacht (MDL-84577), Bildautoren-Felder wurden entfernt (MDL-83909) und der Badges-Bericht wurde verbessert (MDL-82904, MDL-82905).

### SMS-Benachrichtigungen

Moodle 5.0 ergänzte SMS als Benachrichtigungskanal (MDL-83518). Aufgaben-Benachrichtigungen waren die ersten, die diesen Kanal nutzen. Das Modica-SMS-Gateway-Plugin wurde aufgenommen (MDL-79329), und asynchrone Zustellung wurde unterstützt, damit SMS-Versand nicht den Request-Zyklus blockiert (MDL-81015).

### Bootstrap 5

MDL-75669 aktualisierte das Boost-Theme auf Bootstrap 5.x. Bootstrap 4 und Bootstrap 5 verwenden unterschiedliche Klassennamen, JavaScript-Datenattribute und Grid-Verhalten. Moodle enthält Kompatibilitätsschichten für beide (MDL-84324 für jQuery, MDL-84450 für Datenattribute, MDL-80519 für SCSS). Benutzerdefinierte Themes, die Bootstrap-4-Interna direkt verwenden, sollten vor dem Produktionseinsatz überarbeitet werden.

### Quiz und Fragenbank

Die Fragenbank in Moodle 5.0 wurde um erhebliche Filtermöglichkeiten erweitert: nach Änderungsdatum, Fragen-ID, Name, Typ, Status, Bearbeiter, Eigentümer sowie Fragentext oder Feedback (MDL-83859 bis MDL-83863, MDL-84191). Geteilte Fragenbanken wurden benutzbarer, mit "Fragen verwenden"-Berechtigung standardmäßig für die Rolle "Nicht-editierender Lehrer" (MDL-84576).

Neue Quiz-Versuchszustände und asynchrone Versuchserstellung (MDL-68806) ermöglichen den Start von Quizzen ohne blockierende Datenbankschreibvorgänge, was bei großen gleichzeitigen Prüfungssitzungen wichtig ist.

### Bewertungsbuch und Aufgaben

MDL-80984 implementierte generische Strafen im Bewertungsbuch. Aufgaben erhielten Einreichungsbestätigung mit Dateiliste (MDL-84387), zusätzliche Datenfelder für Benachrichtigungsanpassung (MDL-84733) und einen "Bewertet"-Statusfilter auf der Einreichungsseite (MDL-75292).

### Multi-Faktor-Authentifizierung

Die MFA-Einrichtungsseiten wurden deutlich verbessert (MDL-83516, MDL-79958). Die Faktortabelle zeigt nun nützlichere Informationen für Administratoren, und jede Faktor-Einstellungsseite enthält Erklärungen dazu, was der Faktor tut.

## Upgrade-Checkliste für Installationen, die Moodle 5.0 passieren

Wenn Ihre aktuelle Version 4.2.3 oder neuer ist und Sie auf eine 5.x-Version upgraden, vermeidet diese Reihenfolge Überraschungen.

**Vor dem Start:**

- Bestätigen, dass PHP 8.2 oder neuer, 64-Bit, mit geladener sodium-Erweiterung und max_input_vars von mindestens 5000 vorhanden ist
- Datenbankversion auf Moodle-5.0-Untergrenzen prüfen (PostgreSQL 14, MySQL 8.4, MariaDB 10.11)
- Jedes aktive Plugin im Moodle-Plugin-Verzeichnis auf Moodle-5.0-Kompatibilität prüfen
- Jede Nutzung von Atto, Chat, Survey, auth_cas oder MNet auflisten und vor dem Upgrade lösen
- Bei Oracle-Betrieb: vollständige Datenbankmigration auf einen unterstützten Datenbankserver einplanen
- Datenbankpräfix auf maximal 10 Zeichen prüfen

**Während des Upgrades:**

- Code-Verzeichnis, moodledata und Datenbank sichern bevor irgendetwas geändert wird
- Wartungsmodus aktivieren
- Code sauber ersetzen statt über das bestehende Verzeichnis zu kopieren
- Upgrade auf Produktionsservern per CLI ausführen: `php admin/cli/upgrade.php`
- Nach dem Upgrade alle Caches leeren

**Nach dem Upgrade:**

- Anmeldung für jede Rolle testen: Administrator, Lehrender, Studierender
- Aktivitäten testen, die auf die neue Kursübersicht migriert wurden
- TinyMCE auf korrektes Rendern und Speichern in den am häufigsten genutzten Aktivitäten prüfen
- SSO-Integration prüfen, falls auth_cas verwendet wurde
- Bestätigen, dass Cron läuft und geplante Aufgaben abgeschlossen werden

Für Installationen, die direkt auf Moodle 5.2 wechseln, lesen Sie auch den [Moodle-5.2-Upgrade-Leitfaden](/de/blog/moodle-5-2-upgrade-guide).

## Sollten Sie bei Moodle 5.0 stoppen oder direkt auf 5.2?

Stoppen Sie nicht bei Moodle 5.0. Es hat End of Life erreicht und erhält keine Fehlerbehebungen oder Sicherheits-Patches mehr. Wenn Sie jetzt ein Upgrade planen, zielen Sie auf Moodle 5.2 oder die aktuelle unterstützte Version. Nutzen Sie Moodle 5.0 nur als Zwischenstopp, wenn Ihr Upgrade-Pfad es erfordert, und fahren Sie dann sofort fort.

## FAQ

### Kann ich direkt von Moodle 4.1 auf Moodle 5.0 upgraden?

Nein. Moodle 5.0 erfordert als Ausgangsversion Moodle 4.2.3 oder neuer. Upgraden Sie zuerst auf eine unterstützte Moodle-4.2.x-Version oder neuer.

### Erhält Moodle 5.0 noch Sicherheits-Patches?

Nein. Moodle 5.0 hat End of Life. Wenn Sie auf Moodle 5.0 sind, upgraden Sie auf eine unterstützte Version.

### Werden meine Atto-Inhalte nach dem Upgrade auf Moodle 5.0 kaputt gehen?

Von Atto gespeicherte Inhalte sind HTML in der Datenbank. Dieses HTML verschwindet beim Upgrade nicht. Was sich ändert, ist der Editor für neue Inhalte: TinyMCE. Bestehende Inhalte sollten korrekt gerendert werden.

### Muss ich vor dem Upgrade von Oracle migrieren?

Ja. Oracle-Unterstützung wurde in Moodle 5.0 entfernt. Das Installationsprogramm stoppt bei einem Oracle-Datenbankserver. Sie müssen Ihre Daten zuerst auf PostgreSQL, MySQL oder MariaDB migrieren.

### Was ersetzt Chat und Survey?

Moodle liefert keine Ersatz-Core-Aktivitäten. Typische Alternativen sind Plugins aus dem Moodle-Plugin-Verzeichnis oder externe Tools über LTI. Für Chat deckt BigBlueButton einige Anwendungsfälle ab. Für Survey-ähnliche Datenerhebung deckt die Feedback-Aktivität viele der gleichen Szenarien ab.

### Bricht Bootstrap 5 mein benutzerdefiniertes Theme?

Möglicherweise, je nach Theme-Aufbau. Moodle enthält Kompatibilitätsschichten, aber diese decken nicht jeden Randfall ab. Themes, die Bootstrap-4-Interna direkt verwenden, sollten in Staging gegen Moodle 5.0 getestet werden.

### Ist das neue KI-Subsystem verpflichtend?

Nein. Die KI-Funktionen in Moodle 5.0 sind opt-in. Sie erfordern die Konfiguration eines Providers und eine explizite Aktivierung. Eine Installation ohne konfigurierten KI-Provider stellt Nutzern keine KI-Funktionen zur Verfügung.
