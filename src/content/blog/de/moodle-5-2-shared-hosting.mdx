## Die ehrliche Antwort

Moodle 5.2 kann auf Shared Hosting laufen, aber nur wenn der Host genug Kontrolle über Document Root, PHP-Version, Datenbankversion, Router-Regeln, Composer, Cron und `moodledata`-Sicherheit gibt. Viele Shared-Hosting-Tarife scheitern an mindestens einem dieser Punkte.

Die Nachfrage im Moodle.org-Forum ist deutlich: [“Shared Hosting problem [resolved]”](https://moodle.org/mod/forum/discuss.php?d=470266) hat 77 Antworten, dazu kommen Diskussionen über GoDaddy, Hostinger, cPanel, Unterordner, Document Roots und Routing. Moodle 5.x hat verändert, was “einfach in public_html hochladen” bedeutet.

Die Symptome sind konkret: `/admin/index.php` liefert 404, Moodle warnt, dass das Root-Verzeichnis nicht öffentlich sein darf, oder `config.php` sagt, dass `$CFG->wwwroot` nicht mit `/public` enden soll. Das `public`-Verzeichnis soll veröffentlicht sein; `/public` soll aber nicht Teil der sichtbaren Moodle-URL werden.

## Warum Moodle 5.x Shared Hosting stärker fordert

Moodle 5.1 führte das `public`-Verzeichnis ein. Die [Upgrade-Dokumentation für 5.2](https://docs.moodle.org/502/en/Upgrading) sagt, dass der Webserver Moodle aus `public` bedienen soll, während sensible Dateien außerhalb bleiben.

Auf einem VPS ist das normal:

```apache
DocumentRoot /var/www/moodle/public
```

Auf Shared Hosting ist die Hauptdomain oft fest verdrahtet auf:

```text
public_html
```

Genau daraus entsteht der Konflikt. Wenn der Host die Domain nicht auf `moodle/public` zeigen lassen kann, brauchen Sie Symlink, Subdomain, Alias oder Rewrite-Regeln.

## Die Shared-Hosting-Checkliste

| Anforderung | Warum sie zählt |
| --- | --- |
| Domain-Document-Root auf `moodle/public` setzbar | Moodle 5.x will nur `public` öffentlich machen |
| Symlinks erlaubt | Hilft bei festem `public_html` |
| PHP 8.3 oder 8.4 für Web und CLI | Moodle 5.2 benötigt PHP 8.3+ |
| PHP-Erweiterungen vorhanden | `sodium`, `intl`, `mbstring`, `soap`, etc. |
| Unterstützte Datenbank | MariaDB 10.11, MySQL 8.4, PostgreSQL 16 oder SQL Server |
| Composer mit richtigem PHP | `vendor` kann fehlen |
| `.htaccess` oder Rewrite-Regeln | Notwendig, wenn `FallbackResource` nicht geht |
| Cron zuverlässig | Moodle hängt an geplanten Aufgaben |
| `moodledata` außerhalb Webzugriff | Sicherheitsanforderung |
| Logs sichtbar | Ohne Logs wird Debugging Raten |

Wenn der Host diese Fragen nicht klar beantwortet, planen Sie Zeitverlust ein.

## cPanel, Hostinger, GoDaddy und Subdomains

Der typische cPanel-Weg ist ein Addon Domain oder eine Subdomain mit editierbarem Document Root:

```text
moodle.example.com -> /home/account/moodle/public
```

Das Elternverzeichnis liegt dann hier:

```text
/home/account/moodle
```

und nur `public` wird veröffentlicht.

Manche Hostinger-ähnlichen Panels erlauben eine öffentliche Ordnerauswahl direkt. Manche GoDaddy-Tarife sind stärker eingeschränkt. Der Markenname ist weniger wichtig als die tatsächlichen Kontrollen Ihres Tarifs.

## Wenn der Host den Document Root nicht ändern kann

| Option | Wann sie funktioniert | Risiko |
| --- | --- | --- |
| Symlink von `public_html` nach `moodle/public` | Host erlaubt Symlinks | Kann andere Sites stören |
| Addon Domain oder Subdomain | Benutzerdefinierter Document Root möglich | URL muss geplant werden |
| `.htaccess`-Rewrite | Rewrite-Regeln funktionieren sauber | Fragiler als korrekter Document Root |

Machen Sie nicht das gesamte Moodle-Verzeichnis öffentlich.

## Router und Composer auf Shared Hosting

Die Dokumentation [Configuring the Router](https://docs.moodle.org/502/en/Configuring_the_Router) beschreibt `FallbackResource`, `try_files` und Rewrite-Regeln. Auf Shared Hosting bleibt oft nur `.htaccess`. Legen Sie die Regel in `public`.

Wenn der Systemstatus scheitert, lesen Sie [Moodle 5.2 Router nicht korrekt konfiguriert](/de/blog/moodle-router-not-correctly-configured).

Für Composer kann Moodle benötigen:

```bash
composer install --no-dev --classmap-authoritative
```

Fragen Sie:

- Gibt es SSH?
- Gibt es Composer?
- Nutzt Composer PHP 8.3 oder 8.4?
- Können Sie ein vollständiges Artefakt mit `vendor` hochladen?

Wenn nicht, lesen Sie [Moodle Composer vendor directory not found](/de/blog/moodle-vendor-directory-not-found).

## Shared Hosting oder VPS?

| Bedarf | Shared Hosting | VPS |
| --- | --- | --- |
| Document Root | Manchmal gesperrt | Voll kontrollierbar |
| Router-Konfiguration | `.htaccess` oder Panel-Limits | Apache/Nginx-Konfiguration |
| PHP-FPM | Host-definiert | Voll kontrollierbar |
| Datenbankversion | Host-definiert | Voll kontrollierbar |
| Composer | Oft eingeschränkt | Voll kontrollierbar |
| Cron | Panel-Limits | System-Cron |
| Logs | Teilweise | Vollständig |

Wenn Moodle zahlende Lernende, Compliance-Training oder eine Schule trägt, lohnt sich die Kontrolle eines VPS oder Managed Moodle Hosting meist.

## FAQ

### Läuft Moodle 5.2 auf cPanel?

Ja, wenn cPanel eine Domain oder Subdomain auf `moodle/public` zeigen lässt und PHP, Datenbank, Rewrite-Regeln, Cron und privates `moodledata` passen.

### GoDaddy oder Hostinger?

Es hängt vom Tarif ab. Prüfen Sie die tatsächlichen Kontrollen, nicht nur den Namen.

### Ist ein Symlink zu `public` sicher?

Er kann sicher sein, wenn er nur auf `public` zeigt. Veröffentlichen Sie nicht das Elternverzeichnis.

### Sollte ich MoodleCloud nutzen?

Nutzen Sie MoodleCloud oder Managed Hosting, wenn Sie Moodle ohne Serveradministration wollen. Nutzen Sie einen VPS, wenn Sie Kontrolle wollen.
