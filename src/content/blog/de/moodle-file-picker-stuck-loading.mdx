## Schnelldiagnose

Wenn die Moodle-Dateiauswahl oder ein Upload-Feld nach dem Upgrade auf 5.2 endlos lädt, beginnen Sie mit Caches, JavaScript-Fehlern, Theme-Overrides, Repository-Plugins, Upload-Limits und Routing. Der Spinner bedeutet: Die Seite wurde gerendert, aber der Browser bekam keine gültige Antwort für die Dateiauswahl-Anfrage.

Die Moodle.org-Diskussion [“Upgrade to 5.2 has broken file uploads where the box now never loads”](https://moodle.org/mod/forum/discuss.php?d=474506) beschreibt genau das: Box und Button der File Picker laden nie. Eine verwandte Diskussion, [“Students can't upload files after upgrading to 5.2”](https://moodle.org/mod/forum/discuss.php?d=474005), zeigt denselben Schmerz aus Sicht der Lernenden.

## Warum die Seite laden kann, während die Dateiauswahl scheitert

Die Dateiauswahl hängt an Moodle-JavaScript, AJAX-Endpunkten, Repository-Plugins, Sessions, Entwurfs-Dateibereichen, Serverlimits, Rechten und Theme-Templates. Eine Moodle-Seite kann normal aussehen, während die Dateiauswahl im Hintergrund scheitert.

Deshalb reicht “die Seite lädt” nicht. Sie müssen die Anfrage hinter dem Spinner sehen.

## Erster Fix: Caches leeren

Nach dem Upgrade:

`Website-Administration > Entwicklung > Alle Caches löschen`

Oder per CLI:

```bash
php admin/cli/purge_caches.php
```

Die [Moodle-5.2-Upgrade-Dokumentation](https://docs.moodle.org/502/en/Upgrading) nennt fehlende Funktionen wie die Dateiauswahl ausdrücklich als Fall, bei dem manuelle Cache-Löschung helfen kann.

## Browser-Konsole und Netzwerk-Tab prüfen

Öffnen Sie die defekte Seite, dann die Entwicklertools, und laden Sie neu. Suchen Sie nach:

- JavaScript-Fehlern;
- fehlgeschlagenen Anfragen mit 403, 404, 500 oder 503;
- AJAX-Antworten mit HTML statt JSON;
- blockiertem Mixed Content nach HTTPS-Umstellung;
- Anfragen an falschen Host oder Pfad.

Der erste fehlgeschlagene Netzwerk-Request ist meist der beste Hinweis.

## Debugging in Staging aktivieren

Aktivieren Sie in einer Staging-Kopie:

`Website-Administration > Entwicklung > Debugging`

Setzen Sie:

- Debug messages: `DEVELOPER`
- Display debug messages: nur in Staging

Reproduzieren Sie den Fehler und lesen Sie zusätzlich die Serverlogs. In Produktion besser in Dateien loggen.

## Theme ausschließen

Wechseln Sie in Staging temporär auf Boost. Testen Sie:

1. Datei-Ressource hinzufügen;
2. Aufgabe abgeben;
3. Kursbild hochladen;
4. Dateiauswahl als Trainer öffnen;
5. Upload als Lernender testen.

Wenn Boost funktioniert und das Custom Theme nicht, suchen Sie nach veraltetem Template, AMD-Modul, Renderer Override oder JavaScript, das altes Markup erwartet.

## Repository- und Datei-Plugins ausschließen

Die Dateiauswahl lädt Repositories. Deaktivieren Sie nicht notwendige Repository-Plugins in Staging.

| Komponente | Was brechen kann |
| --- | --- |
| Dateisystem-Repository | Pfad oder Rechte |
| Google Drive / OneDrive | OAuth, Callback, Token oder Service Account |
| Eigenes Repository-Plugin | Nicht Moodle-5.2-kompatibel |
| Medien-Plugins | JavaScript- oder Filterkonflikt |
| Antivirus | Anfrage blockiert oder Timeout |

Aktualisieren Sie das auslösende Plugin oder deaktivieren Sie es bis zur kompatiblen Version.

## PHP- und Moodle-Limits prüfen

```ini
upload_max_filesize = 128M
post_max_size = 128M
max_file_uploads = 20
max_input_vars = 5000
max_execution_time = 300
memory_limit = 256M
```

Danach prüfen Sie:

- `Website-Administration > Sicherheit > Website-Sicherheitseinstellungen`
- Upload-Limits im Kurs;
- Abgabe-Limits;
- Repository-Einstellungen.

`max_input_vars` muss laut Moodle 5.2 mindestens 5000 betragen.

## `moodledata` prüfen

Moodle speichert hochgeladene Dateien in `moodledata`, nicht im Code-Verzeichnis.

```bash
ls -ld /path/to/moodledata
```

Der Webserver muss dort schreiben können, aber das Verzeichnis darf nicht öffentlich erreichbar sein. Verschieben Sie `moodledata` nicht nach `public_html`, nur um Rechte zu umgehen.

## `public` und Router prüfen

Bestätigen Sie:

- Webroot zeigt auf `moodle/public`;
- `$CFG->wwwroot` hat Schema und Host korrekt;
- Router-Checks bestehen;
- Reverse Proxy erhält HTTPS und Host.

Wenn der Router scheitert, beheben Sie das zuerst mit [Moodle 5.2 Router nicht korrekt konfiguriert](/de/blog/moodle-router-not-correctly-configured).

## Praktische Reihenfolge

1. Alle Caches leeren.
2. Mit geöffneten Entwicklertools reproduzieren.
3. Ersten fehlgeschlagenen Netzwerk-Request notieren.
4. Debugging in Staging aktivieren.
5. Temporär auf Boost wechseln.
6. Drittanbieter-Repositories deaktivieren.
7. PHP- und Moodle-Limits prüfen.
8. `moodledata` prüfen.
9. Router und Webroot prüfen.
10. Cron und Ad-hoc-Tasks ausführen.

## FAQ

### Warum lädt die Moodle-Dateiauswahl endlos?

Meist wartet der Browser auf eine AJAX-Antwort, die fehlschlägt, ungültiges JSON liefert oder durch JavaScript, Theme, Plugin, Session, Routing oder Rechte blockiert wird.

### Hilft Cache-Leeren wirklich?

Ja. Moodle nennt das nach dem 5.2-Upgrade ausdrücklich für fehlende Funktionen wie die Dateiauswahl.

### Soll ich Moodle neu installieren?

Nein. Finden Sie zuerst die fehlschlagende Anfrage.
