## La version courte

Moodle 5.0 est sorti le 14 avril 2025 et est déjà en fin de vie. Ce n'était pas une version LTS, donc la communauté est passée à autre chose rapidement. Cela ne le rend pas sans intérêt. Si vous êtes sur Moodle 4.x et que vous visez la 5.2 ou une version ultérieure, votre chemin de mise à niveau passe par les exigences que Moodle 5.0 a figées : PHP 8.2 minimum, seuils de bases de données rehaussés, Bootstrap 5, et la suppression définitive d'Atto, Oracle, Chat, Survey et MNet. Ces changements ne disparaissent pas dans les versions suivantes. Ils ont commencé ici.

Cette page explique ce qui a vraiment changé dans Moodle 5.0, ce qui a été supprimé définitivement, et ce qu'il faut vérifier avant une mise à niveau qui inclut cette version dans son chemin.

## Pourquoi Moodle 5.0 compte, même si vous le sautez

La numérotation des versions Moodle suit un schéma prévisible : chaque quatrième version est une version Long-Term Support. Moodle 4.5 LTS a précédé la 5.0, et Moodle 5.1 était le prochain candidat LTS ciblé par la plupart des sites. Moodle 5.0 est une version standard, supportée uniquement jusqu'à la sortie de la version standard suivante, ce qui explique pourquoi son EOL est arrivé si vite.

Mais les changements d'exigences de la 5.0 sont réels et se propagent. Si votre site tourne encore sur PHP 8.1, MariaDB 10.6 ou MySQL 8.0 (avant 8.4), ou si vous utilisez Oracle, Moodle 5.0 est la version où ces configurations ont cessé de fonctionner. Ce mur ne s'adoucit pas en 5.1 ou 5.2.

## Exigences serveur pour Moodle 5.0

Ce sont des minimums. Tourner au minimum convient pour un serveur de test ; la production devrait utiliser le dernier point release stable de chaque composant.

| Exigence | Minimum Moodle 5.0 | Notes |
| --- | --- | --- |
| Version source | Moodle 4.2.3 ou plus récent | Impossible de sauter depuis 4.1 ou plus ancien |
| PHP | 8.2.0 | 8.3.x et 8.4.x aussi supportés |
| Architecture PHP | 64 bits uniquement | 32 bits abandonnés depuis Moodle 4.1 |
| Extension PHP | sodium | Requise, pas optionnelle |
| Paramètre PHP | max_input_vars >= 5000 | Les valeurs inférieures cassent les soumissions de formulaires |
| PostgreSQL | 14 | Relevé depuis 13 |
| MySQL | 8.4 | Relevé depuis 8.0 |
| MariaDB | 10.11.0 | Relevé depuis 10.6 |
| Aurora MySQL | 8.0 | Versionné comme MySQL, pas en version Aurora interne |
| Microsoft SQL Server | 2017 | Inchangé |
| Oracle | Supprimé | Non supporté depuis Moodle 5.0 |

La longueur du préfixe de base de données est limitée à 10 caractères depuis Moodle 4.3. Si votre `$CFG->prefix` est plus long, la mise à niveau échouera avant de démarrer.

## Ce qui a été supprimé dans Moodle 5.0

C'est la liste qui surprend les administrateurs qui ne lisent pas les notes de version avant la mise à niveau.

### L'éditeur de texte Atto

MDL-83282 a supprimé Atto définitivement. TinyMCE est désormais le seul éditeur de texte enrichi inclus. Si des plugins, thèmes ou formulaires personnalisés référencent des API ou des templates spécifiques à Atto, ils ne fonctionneront plus après la mise à niveau.

TinyMCE a aussi reçu un plugin d'accessibilité (MDL-84125), la désactivation de plugins par rôle (MDL-84126) et une meilleure expérience d'ajout de médias (MDL-78428).

### La base de données Oracle

MDL-83172 a abandonné le support d'Oracle entièrement. Si votre institution fait tourner Moodle sur Oracle, la 5.0 est un arrêt brutal. Il n'y a pas de chemin de migration dans Moodle lui-même ; vous devez exporter vos données et reconstruire sur un moteur supporté avant la mise à niveau. PostgreSQL est la cible recommandée pour les sites à fort volume de reporting.

### Les activités Chat et Survey

MDL-82457 a supprimé le module Chat et le module Survey du noyau Moodle. Les sites utilisant ces activités doivent vérifier qui en dépend avant de mettre à niveau. Le module Survey stockait des données de réponses qui ne migrent pas automatiquement vers une alternative.

### Les plugins d'authentification

MDL-78778 a supprimé le plugin d'authentification CAS (auth_cas). Les sites utilisant CAS pour le SSO doivent migrer vers une alternative avant la mise à niveau. SAML2, OAuth2 ou LDAP sont les remplaçants courants selon votre fournisseur d'identité. Pour un aperçu des options SSO, consultez [Options SSO pour les plateformes d'apprentissage](/fr/blog/sso-options-for-learning-platforms).

### MNet

MDL-84652 a supprimé tous les plugins MNet. MNet était le propre système de mise en réseau pair-à-pair de Moodle. La plupart des sites l'avaient déjà abandonné, mais si le vôtre avait des connexions MNet actives pour l'inscription ou l'authentification, elles ne fonctionneront plus après la mise à niveau.

### Autres suppressions

MDL-84265 a supprimé le support SQLite de la couche de base de données. MDL-83703 a supprimé l'ancien format de découverte subplugins.php. MDL-84107 a supprimé le backend de machine learning PHP. MDL-61232 a mis admin/process_email.php en retraite. Ces changements n'affectent pas les sites de production typiques, mais ils comptent si votre configuration en dépendait.

## Ce qui est nouveau dans Moodle 5.0

### Page de vue d'ensemble centralisée des cours

Le changement le plus visible pour les étudiants et les enseignants est la nouvelle page de vue d'ensemble des activités du cours (MDL-83871). Au lieu de naviguer vers la page d'index de chaque activité, les utilisateurs ont une vue unifiée de toutes les activités d'un cours. Elle utilise des tableaux à la demande (MDL-83872) pour ne pas tout charger d'un coup, et inclut un comptage des alertes (MDL-84602) pour que les enseignants voient d'un coup d'oeil quelles activités nécessitent leur attention.

### Améliorations de l'IA

Moodle 5.0 a étendu le sous-système IA dans quatre directions : un nouveau fournisseur Ollama (MDL-83006) pour des modèles de langage locaux sans API externe, le support de plusieurs instances de fournisseurs (MDL-82977), des paramètres par modèle (MDL-82980) avec ordre des fournisseurs (MDL-83216), et des rapports admin sur l'utilisation de l'IA et l'acceptation des politiques (MDL-83395, MDL-83396).

L'ajout d'Ollama est pratiquement significatif pour les institutions ayant des exigences strictes en matière de résidence des données. Pour un regard réaliste sur les fonctionnalités IA qui aident vraiment dans un LMS, consultez [L'IA dans un LMS : ce qui est réellement utile](/fr/blog/ai-in-an-lms-what-actually-helps).

### Open Badges 3.0

MDL-82905 et les tickets associés ont mis à jour le système de badges de Moodle vers la spécification Open Badges 3.0. Le formulaire de création de badge a été réorganisé et simplifié (MDL-84577), les champs d'auteur d'image ont été supprimés (MDL-83909) et le rapport sur les badges a été amélioré (MDL-82904, MDL-82905).

### Notifications SMS

Moodle 5.0 a ajouté le SMS comme canal de notification (MDL-83518). Les notifications de devoirs ont été les premières à l'utiliser. Le plugin de passerelle SMS Modica a été inclus (MDL-79329), et la livraison asynchrone a été supportée pour que l'envoi de SMS ne bloque pas le cycle de requête (MDL-81015).

### Bootstrap 5

MDL-75669 a mis à niveau le thème Boost vers Bootstrap 5.x. Bootstrap 4 et Bootstrap 5 ont des noms de classes, des attributs de données JavaScript et des comportements de grille différents. Moodle a inclus des couches de compatibilité (MDL-84324 pour jQuery, MDL-84450 pour les attributs de données, MDL-80519 pour SCSS). Les thèmes personnalisés qui utilisent les internals Bootstrap 4 directement doivent être mis à jour et testés avant la production.

### Quiz et banque de questions

La banque de questions de la 5.0 a reçu une expansion significative des filtres : par date de modification, ID de question, nom, type, statut, modificateur, propriétaire et contenu de la question ou du feedback (MDL-83859 à MDL-83863, MDL-84191). Les banques de questions partagées sont aussi devenues plus utilisables, avec la capacité "utiliser les questions" accordée par défaut au rôle d'enseignant non-éditeur (MDL-84576).

### Notes et devoirs

MDL-80984 a implémenté des pénalités génériques dans le carnet de notes. Les devoirs ont reçu une confirmation de remise avec liste de fichiers (MDL-84387), des champs de données supplémentaires pour la personnalisation des notifications (MDL-84733), et un filtre de statut "Noté" sur la page des remises (MDL-75292).

### Authentification multi-facteurs

Les pages de configuration MFA ont été sensiblement améliorées (MDL-83516, MDL-79958). Le tableau des facteurs affiche maintenant des informations plus utiles pour les admins, et chaque page de paramètres de facteur inclut des explications sur ce que fait le facteur.

## Liste de vérification pour les sites qui passent par Moodle 5.0

Si votre version actuelle est 4.2.3 ou plus récente et que vous mettez à niveau vers une version 5.x, cette séquence évite les mauvaises surprises.

**Avant de commencer :**

- Confirmer que PHP est en 8.2 ou plus récent, 64 bits, avec l'extension sodium chargée et max_input_vars à 5000 ou plus
- Vérifier que la version de la base de données respecte les seuils de la 5.0 (PostgreSQL 14, MySQL 8.4, MariaDB 10.11)
- Vérifier chaque plugin actif dans le répertoire de plugins Moodle pour la compatibilité avec la 5.0
- Lister toute utilisation d'Atto, Chat, Survey, auth_cas ou MNet, et résoudre avant la mise à niveau
- Si vous tournez sur Oracle, planifier une migration complète de la base de données vers un moteur supporté
- Vérifier que le préfixe de base de données fait 10 caractères ou moins

**Pendant la mise à niveau :**

- Sauvegarder le répertoire de code Moodle, moodledata et la base de données avant de toucher quoi que ce soit
- Passer le site en mode maintenance
- Remplacer le code proprement plutôt que de copier par-dessus le répertoire existant
- Lancer la mise à niveau en ligne de commande pour les sites de production : `php admin/cli/upgrade.php`
- Purger tous les caches après la mise à niveau

**Après la mise à niveau :**

- Tester la connexion pour chaque rôle : admin, enseignant, étudiant
- Tester les activités migrées vers la nouvelle vue d'ensemble des cours
- Vérifier que TinyMCE rend et sauvegarde correctement dans vos activités les plus utilisées
- Vérifier l'intégration SSO si vous utilisiez auth_cas
- Confirmer que cron tourne et que les tâches planifiées s'exécutent

## Faut-il s'arrêter en 5.0 ou aller directement en 5.2 ?

Ne vous arrêtez pas en 5.0. Elle est déjà en fin de vie et ne reçoit plus ni correctifs ni patchs de sécurité. Si vous planifiez une mise à niveau maintenant, ciblez la 5.2 ou la version supportée au moment de votre mise à niveau. Utilisez la 5.0 uniquement comme étape intermédiaire si votre chemin de mise à niveau l'exige, puis continuez immédiatement.

## FAQ

### Puis-je mettre à niveau directement depuis Moodle 4.1 vers Moodle 5.0 ?

Non. Moodle 5.0 exige une version source de Moodle 4.2.3 ou plus récente. Mettez d'abord à niveau vers une version 4.2.x supportée ou plus récente.

### Moodle 5.0 reçoit-il encore des patchs de sécurité ?

Non. Moodle 5.0 est en fin de vie. Si vous êtes sur la 5.0, mettez à niveau vers une version supportée.

### Mon contenu créé avec Atto sera-t-il cassé après la mise à niveau vers Moodle 5.0 ?

Le contenu sauvegardé par Atto est du HTML stocké en base de données. Ce HTML ne disparaît pas lors de la mise à niveau. Ce qui change, c'est l'éditeur utilisé pour créer de nouveaux contenus. Le contenu existant devrait s'afficher correctement.

### Dois-je migrer depuis Oracle avant la mise à niveau ?

Oui. Le support Oracle a été supprimé dans Moodle 5.0. L'installeur s'arrêtera avec une base Oracle. Vous devez d'abord migrer vos données vers PostgreSQL, MySQL ou MariaDB.

### Qu'est-ce qui remplace Chat et Survey ?

Moodle ne fournit pas de remplaçants en tant qu'activités du noyau. Les alternatives typiques sont des plugins tiers du répertoire de plugins Moodle, ou des outils externes intégrés via LTI. Pour le chat, BigBlueButton couvre certains cas d'usage. Pour la collecte de données de type survey, l'activité Feedback couvre beaucoup des mêmes scénarios.

### Bootstrap 5 va-t-il casser mon thème personnalisé ?

Peut-être, selon la façon dont le thème est construit. Moodle a inclus des couches de compatibilité pour la transition Bootstrap 4 vers 5, mais elles ne couvrent pas tous les cas limites. Les thèmes personnalisés qui utilisent des internals Bootstrap 4 directement doivent être testés en préproduction.

### Le nouveau sous-système IA est-il obligatoire ?

Non. Les fonctionnalités IA de Moodle 5.0 sont optionnelles. Elles nécessitent la configuration d'un fournisseur et une activation explicite. Un site sans fournisseur IA configuré n'expose pas de fonctionnalités IA aux utilisateurs.
