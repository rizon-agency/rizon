## La versión corta

Actualizar Moodle 5.1 a 5.2 suele ser tranquilo cuando el servidor está preparado antes de tocar el código. Los fallos que parecen misteriosos después de la actualización suelen venir de cinco sitios: el directorio `public` introducido en Moodle 5.1, la configuración del router, las dependencias de Composer, plugins que todavía esperan rutas antiguas y cachés que no se regeneraron bien.

No lo trates como una sustitución de archivos. Trátalo como un despliegue controlado: clona producción, revisa requisitos, mueve plugins con intención, ejecuta la actualización en un entorno de pruebas y repite los mismos pasos en producción.

## Por qué Moodle 5.2 está pillando a tanta gente

El foro Installing and Upgrading Help de Moodle.org está lleno de síntomas de Moodle 5.x: checks de router fallando, menús desaparecidos, imágenes rotas, cajas de subida que se quedan cargando, problemas en bancos de preguntas, `Class "Mustache_Engine" not found` y errores de Composer.

No son seis problemas aislados. Moodle 5.1 movió el código web a `public` y añadió el router al camino de las peticiones. Moodle 5.2 elevó requisitos como PHP 8.3 y exige venir desde Moodle 4.4 o posterior. Las [notas de Moodle 5.2](https://moodledev.io/general/releases/5.2) y la [guía de actualización](https://docs.moodle.org/502/en/Upgrading) son la fuente de verdad.

## Antes de tocar producción

Prepara una lista con servidor, código y datos.

| Área | Qué comprobar | Por qué importa |
| --- | --- | --- |
| PHP | Moodle 5.2 requiere PHP 8.3 o superior | El check de entorno puede bloquear la actualización |
| Base de datos | MariaDB 10.11, MySQL 8.4, PostgreSQL 16 u otra versión soportada | Las versiones antiguas fallan antes de que Moodle arranque |
| Raíz web | El dominio apunta a `moodle/public` | Si se publica todo Moodle, 5.x rompe o avisa de seguridad |
| Router | Apache, Nginx, IIS u OpenLiteSpeed envía rutas sin archivo real a `r.php` | Las rutas limpias dependen de ello |
| Composer | Existe `vendor` | Moodle 5.1+ comprueba dependencias instaladas |
| Plugins | Cada plugin es compatible con 5.2 | Temas, formatos y repositorios son causas habituales |
| Cachés | Puedes purgarlas tras actualizar | Moodle menciona el file picker como caso que puede necesitar purga manual |

El objetivo no es hacer papeleo. Es que la actualización sea aburrida.

## 1. Comprueba el camino de actualización

En el sitio actual, ve a `Administración del sitio > Servidor > Entorno` y cambia la versión objetivo a Moodle 5.2. Corrige todos los avisos antes de empezar.

Moodle 5.2 solo acepta actualización desde Moodle 4.4 o posterior. Si estás en 4.3, 4.2 o anterior, actualiza primero a una versión intermedia soportada.

| Requisito | Mínimo Moodle 5.2 |
| --- | --- |
| Versión origen | Moodle 4.4 o posterior |
| PHP | 8.3.0 |
| MariaDB | 10.11.0 |
| MySQL | 8.4 |
| PostgreSQL | 16 |
| SQL Server | 2019 |
| `max_input_vars` | 5000 |
| Arquitectura PHP | 64 bits |

Comprueba también extensiones como `sodium`, `intl`, `mbstring`, `soap`, `zip` y `fileinfo`.

## 2. Haz copia de las tres cosas reales

Copia el código Moodle, el directorio `moodledata` y la base de datos. Una copia solo de archivos no es un plan de vuelta atrás. Los archivos de cursos viven en `moodledata`; los registros de aprendizaje viven en la base.

En producción, hazlo en modo mantenimiento o en una ventana tranquila. Si cron está corriendo, espera a que terminen las tareas activas.

## 3. Sustituye el código limpiamente

No copies Moodle 5.2 encima del directorio antiguo. Aparta el código viejo, descomprime la versión nueva y copia solo lo que corresponde.

```bash
mv moodle moodle.backup
tar xvzf moodle-latest-5.2.tgz
cp moodle.backup/config.php moodle/
```

Después copia plugins ya verificados en las rutas correctas de Moodle 5.x. Muchos deben vivir bajo `public`.

```bash
cp -pr moodle.backup/theme/mytheme moodle/public/theme/mytheme
cp -pr moodle.backup/mod/mymod moodle/public/mod/mymod
```

Si usas Git, sigue la guía [Git for Administrators](https://docs.moodle.org/502/en/GIT) y apunta a la rama estable correcta.

## 4. Trata los plugins como bloqueantes

Que una carpeta se copie no significa que el plugin sea compatible.

| Zona de plugin | Fallo que puedes ver |
| --- | --- |
| Tema | Menús invisibles, cajones rotos, selector de archivos ausente |
| Formato de curso | Secciones que no renderizan |
| Tipo de pregunta | Errores en banco de preguntas |
| Repositorio | Selector de archivos que se queda cargando |
| Matrícula/pago | Usuarios sin acceso al curso pagado |
| Informes/local | Errores de clase o namespace en administración |

Si aparece `Class "Mustache_Engine" not found`, sospecha de un tema o plugin que llama al nombre antiguo de Mustache.

## 5. Apunta el servidor web a `public`

Desde Moodle 5.1, la raíz web debe ser el directorio `public`, no la carpeta padre.

Apache:

```apache
DocumentRoot /var/www/moodle/public

<Directory /var/www/moodle/public>
    AllowOverride None
    Require all granted
</Directory>
```

Nginx:

```nginx
root /var/www/moodle/public;
```

En cPanel o hosting compartido quizá necesites un subdominio, symlink o alias. Si tu host no permite nada de eso, el problema no es Moodle: es que el plan no te da el control que Moodle 5.x necesita.

Para ese tema, lee [¿Puede Moodle 5.2 funcionar en hosting compartido?](/es/blog/moodle-5-2-shared-hosting).

## 6. Configura el router

El router envía peticiones que no corresponden a un archivo real hacia `r.php`.

Apache:

```apache
FallbackResource /r.php
```

Nginx:

```nginx
try_files $uri $uri/ /r.php$is_args$args;
```

Si Moodle dice que una ruta `.php` falsa devuelve 404 en vez de 302, consulta [Moodle 5.2: el router no está configurado correctamente](/es/blog/moodle-router-not-correctly-configured).

## 7. Instala dependencias Composer

Si aparece `Composer vendor directory not found`, ejecuta Composer desde la raíz Moodle, no desde `public`.

```bash
composer install --no-dev --classmap-authoritative
```

Si tu hosting no tiene Composer o shell, construye el artefacto en otro sitio y sube el árbol completo con `vendor`. El diagnóstico completo está en [Moodle: Composer vendor directory not found](/es/blog/moodle-vendor-directory-not-found).

## 8. Ejecuta la actualización y purga cachés

En producción, mejor CLI:

```bash
php admin/cli/upgrade.php
```

Después purga:

`Administración del sitio > Desarrollo > Purgar todas las cachés`

Si el selector de archivos sigue girando, lee [el selector de archivos de Moodle se queda cargando tras actualizar a 5.2](/es/blog/moodle-file-picker-stuck-loading).

## Prueba los flujos reales

No des la actualización por terminada porque carga el dashboard. Prueba login, administración, páginas de curso, edición, subidas, entrega de tareas, cron, plugins e integraciones.

| Síntoma | Primer sitio a revisar |
| --- | --- |
| 404 tras actualizar | Raíz web no apunta a `public` |
| Check de router falla | Regla de router o PHP-FPM |
| `Composer vendor directory not found` | Falta `vendor` |
| Menús rotos | Tema, plugin o caché |
| Selector de archivos cargando | Caché, JavaScript, tema, repositorio o AJAX |
| `Class "Mustache_Engine" not found` | Plugin no compatible con Moodle 5.2 |

## FAQ

### ¿Puedo actualizar directamente de Moodle 5.1 a 5.2?

Sí. Moodle 5.2 soporta actualización desde Moodle 4.4 o posterior.

### ¿Debo mover la raíz web a `public`?

Sí, si no se hizo ya al pasar a Moodle 5.1.

### ¿Navegador o CLI?

Usa CLI en producción cuando puedas. Evita timeouts de navegador, proxy y servidor web.
