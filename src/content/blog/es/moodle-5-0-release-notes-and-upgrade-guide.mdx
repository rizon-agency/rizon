## La versión corta

Moodle 5.0 salió el 14 de abril de 2025 y ya ha llegado a su fin de vida. Nunca fue una versión LTS, así que la comunidad pasó página rápido. Eso no significa que sea irrelevante. Si estás en Moodle 4.x y apuntas a la 5.2 o posterior, tu camino de actualización pasa por los requisitos que Moodle 5.0 dejó fijados: PHP 8.2 mínimo, suelos de base de datos más altos, Bootstrap 5, y la eliminación permanente de Atto, Oracle, Chat, Survey y MNet. Esos cambios no desaparecen en versiones posteriores. Empezaron aquí.

Esta página cubre qué cambió realmente en Moodle 5.0, qué se eliminó de forma permanente, y qué debes verificar antes de una actualización que incluya esta versión en su camino.

## Por qué Moodle 5.0 importa aunque lo saltes

La numeración de versiones de Moodle sigue un patrón predecible: cada cuarta versión es una versión de soporte a largo plazo. Moodle 4.5 LTS precedió a la 5.0, y Moodle 5.1 fue el siguiente candidato LTS al que apuntaba la mayoría de sitios. Moodle 5.0 es una versión estándar, soportada solo hasta que llega la siguiente versión estándar, lo que explica por qué su EOL llegó tan pronto.

Pero los cambios de requisitos de la 5.0 son reales y se propagan. Si tu sitio sigue en PHP 8.1, MariaDB 10.6 o MySQL 8.0 (anterior a 8.4), o si usas Oracle, Moodle 5.0 es la versión donde esas configuraciones dejaron de funcionar. Ese muro no se suaviza en la 5.1 ni en la 5.2.

## Requisitos de servidor para Moodle 5.0

Estos son mínimos. Correr en el mínimo está bien para un servidor de pruebas; producción debería estar en el último point release estable de cada componente.

| Requisito | Mínimo Moodle 5.0 | Notas |
| --- | --- | --- |
| Versión origen | Moodle 4.2.3 o posterior | No se puede saltar desde 4.1 o anterior |
| PHP | 8.2.0 | 8.3.x y 8.4.x también soportados |
| Arquitectura PHP | Solo 64 bits | 32 bits eliminados en Moodle 4.1 |
| Extensión PHP | sodium | Obligatoria, no opcional |
| Parámetro PHP | max_input_vars >= 5000 | Valores inferiores rompen el envío de formularios |
| PostgreSQL | 14 | Subido desde 13 |
| MySQL | 8.4 | Subido desde 8.0 |
| MariaDB | 10.11.0 | Subido desde 10.6 |
| Aurora MySQL | 8.0 | Versionado como MySQL, no versión Aurora interna |
| Microsoft SQL Server | 2017 | Sin cambios |
| Oracle | Eliminado | No soportado desde Moodle 5.0 |

La longitud del prefijo de base de datos está limitada a 10 caracteres desde Moodle 4.3. Si tu `$CFG->prefix` es más largo, la actualización fallará antes de empezar.

## Qué se eliminó en Moodle 5.0

Esta es la lista que sorprende a los administradores que no leen las notas de versión antes de actualizar.

### El editor de texto Atto

MDL-83282 eliminó Atto de forma permanente. TinyMCE es ahora el único editor de texto enriquecido incluido. Si algún plugin, tema o formulario personalizado referencia APIs o plantillas específicas de Atto, dejarán de funcionar tras la actualización.

TinyMCE también recibió un plugin de accesibilidad (MDL-84125), desactivación de plugins por rol (MDL-84126) y una mejor experiencia al añadir medios (MDL-78428).

### La base de datos Oracle

MDL-83172 eliminó el soporte de Oracle por completo. Si tu institución ejecuta Moodle sobre Oracle, la 5.0 es un freno absoluto. No existe un camino de migración dentro de Moodle; debes exportar tus datos y reconstruir en un motor soportado antes de actualizar. PostgreSQL es el destino recomendado para sitios con alto volumen de reporting.

### Las actividades Chat y Survey

MDL-82457 eliminó el módulo Chat y el módulo Survey del núcleo de Moodle. Los sitios que usen estas actividades deben revisar quién depende de ellas antes de actualizar. El módulo Survey almacenaba datos de respuestas que no migran automáticamente a una alternativa.

### Plugins de autenticación

MDL-78778 eliminó el plugin de autenticación CAS (auth_cas). Los sitios que usan CAS para SSO deben migrar a una alternativa antes de actualizar. SAML2, OAuth2 o LDAP son los reemplazos habituales según tu proveedor de identidad. Para un resumen de opciones SSO, consulta [Opciones SSO para plataformas de aprendizaje](/es/blog/sso-options-for-learning-platforms).

### MNet

MDL-84652 eliminó todos los plugins de MNet. MNet era el propio sistema de red entre pares de Moodle. La mayoría de sitios ya había dejado de usarlo, pero si el tuyo tenía conexiones MNet activas para inscripciones o autenticación, dejarán de funcionar tras la actualización.

### Otras eliminaciones

MDL-84265 eliminó el soporte de SQLite de la capa de base de datos. MDL-83703 eliminó el antiguo formato de descubrimiento subplugins.php. MDL-84107 eliminó el backend de machine learning PHP. MDL-61232 retiró admin/process_email.php. Estos cambios no afectan a sitios de producción típicos, pero importan si tu configuración dependía de alguno de ellos.

## Qué hay de nuevo en Moodle 5.0

### Página de resumen centralizado de cursos

El cambio más visible para estudiantes y profesores es la nueva página de resumen de actividades del curso (MDL-83871). En lugar de navegar a la página de índice de cada actividad, los usuarios tienen una vista unificada de todas las actividades de un curso. Usa tablas bajo demanda (MDL-83872) para no cargar todo a la vez, e incluye conteo de alertas (MDL-84602) para que los profesores vean de un vistazo qué actividades requieren atención.

### Mejoras de IA

Moodle 5.0 amplió el subsistema de IA en cuatro direcciones: un nuevo proveedor Ollama (MDL-83006) para modelos de lenguaje locales sin API externa, soporte para múltiples instancias de proveedores (MDL-82977), configuración por modelo (MDL-82980) con orden de proveedores (MDL-83216), e informes de administración sobre uso de IA y aceptación de políticas (MDL-83395, MDL-83396).

La adición de Ollama es prácticamente significativa para instituciones con requisitos estrictos de residencia de datos. Para una visión realista de qué funcionalidades de IA en un LMS realmente ayudan, consulta [IA en un LMS: lo que realmente ayuda](/es/blog/ai-in-an-lms-what-actually-helps).

### Open Badges 3.0

MDL-82905 y tickets relacionados actualizaron el sistema de insignias de Moodle hacia la especificación Open Badges 3.0. El formulario de creación de insignias se reorganizó y simplificó (MDL-84577), se eliminaron los campos de autor de imagen (MDL-83909) y se mejoró el informe de insignias (MDL-82904, MDL-82905).

### Notificaciones SMS

Moodle 5.0 añadió el SMS como canal de notificación (MDL-83518). Las notificaciones de tareas fueron las primeras en usarlo. Se incluyó el plugin de pasarela SMS Modica (MDL-79329), y se soportó la entrega asíncrona para que el envío de SMS no bloquee el ciclo de petición (MDL-81015).

### Bootstrap 5

MDL-75669 actualizó el tema Boost a Bootstrap 5.x. Bootstrap 4 y Bootstrap 5 tienen nombres de clases, atributos de datos JavaScript y comportamiento de cuadrícula diferentes. Moodle incluyó capas de compatibilidad (MDL-84324 para jQuery, MDL-84450 para atributos de datos, MDL-80519 para SCSS). Los temas personalizados que usan internos de Bootstrap 4 directamente necesitan actualización y pruebas antes de producción.

### Quiz y banco de preguntas

El banco de preguntas de la 5.0 recibió una expansión significativa de filtros: por fecha de modificación, ID de pregunta, nombre, tipo, estado, modificador, propietario y contenido de la pregunta o el feedback (MDL-83859 a MDL-83863, MDL-84191). Los bancos de preguntas compartidos también se volvieron más usables, con el permiso "usar preguntas" concedido por defecto al rol de profesor no editor (MDL-84576).

### Calificaciones y tareas

MDL-80984 implementó penalizaciones genéricas en el libro de calificaciones. Las tareas recibieron confirmación de entrega con lista de archivos (MDL-84387), campos de datos adicionales para personalizar notificaciones (MDL-84733), y un filtro de estado "Calificado" en la página de entregas (MDL-75292).

### Autenticación multifactor

Las páginas de configuración de MFA mejoraron notablemente (MDL-83516, MDL-79958). La tabla de factores ahora muestra información más útil para los administradores, y cada página de configuración de factor incluye explicaciones sobre lo que hace ese factor.

## Lista de comprobación para sitios que pasan por Moodle 5.0

Si tu versión actual es 4.2.3 o posterior y vas a actualizar a una versión 5.x, esta secuencia evita sorpresas.

**Antes de empezar:**

- Confirmar que PHP es 8.2 o posterior, 64 bits, con la extensión sodium cargada y max_input_vars en 5000 o más
- Verificar que la versión de base de datos cumple los suelos de la 5.0 (PostgreSQL 14, MySQL 8.4, MariaDB 10.11)
- Comprobar cada plugin activo en el directorio de plugins de Moodle para compatibilidad con la 5.0
- Listar cualquier uso de Atto, Chat, Survey, auth_cas o MNet, y resolverlo antes de actualizar
- Si usas Oracle, planificar una migración completa de la base de datos a un motor soportado
- Verificar que el prefijo de base de datos tiene 10 caracteres o menos

**Durante la actualización:**

- Hacer copia de seguridad del directorio de código Moodle, moodledata y la base de datos antes de tocar nada
- Poner el sitio en modo mantenimiento
- Reemplazar el código limpiamente en lugar de copiar encima del directorio existente
- Ejecutar la actualización vía CLI en sitios de producción: `php admin/cli/upgrade.php`
- Purgar todas las cachés tras completar la actualización

**Después de la actualización:**

- Probar el inicio de sesión para cada rol: administrador, profesor, estudiante
- Probar las actividades migradas a la nueva vista de resumen del curso
- Verificar que TinyMCE renderiza y guarda correctamente en tus actividades más usadas
- Comprobar la integración SSO si usabas auth_cas
- Confirmar que cron está corriendo y que las tareas programadas se completan

Para sitios que van directamente a la 5.2, lee también la [guía de actualización de Moodle 5.2](/es/blog/moodle-5-2-upgrade-guide).

## ¿Deberías quedarte en la 5.0 o ir directamente a la 5.2?

No te quedes en la 5.0. Ya está en fin de vida y no recibe ni correcciones de errores ni parches de seguridad. Si planeas una actualización ahora, apunta a la 5.2 o a la versión soportada en ese momento. Usa la 5.0 solo como parada intermedia si tu camino de actualización lo requiere, y continúa inmediatamente.

## FAQ

### ¿Puedo actualizar directamente desde Moodle 4.1 a Moodle 5.0?

No. Moodle 5.0 requiere una versión origen de Moodle 4.2.3 o posterior. Actualiza primero a una versión 4.2.x soportada o posterior.

### ¿Sigue recibiendo Moodle 5.0 parches de seguridad?

No. Moodle 5.0 está en fin de vida. Si estás en la 5.0, actualiza a una versión soportada.

### ¿Se romperá mi contenido creado con Atto tras actualizar a Moodle 5.0?

El contenido guardado por Atto es HTML almacenado en la base de datos. Ese HTML no desaparece al actualizar. Lo que cambia es el editor para crear nuevo contenido: TinyMCE. El contenido existente debería renderizarse correctamente.

### ¿Tengo que migrar desde Oracle antes de actualizar?

Sí. El soporte de Oracle fue eliminado en Moodle 5.0. El instalador se detendrá con una base de datos Oracle. Primero debes migrar tus datos a PostgreSQL, MySQL o MariaDB.

### ¿Qué reemplaza a Chat y Survey?

Moodle no incluye actividades de reemplazo en el núcleo. Las alternativas habituales son plugins de terceros del directorio de plugins de Moodle, o herramientas externas integradas vía LTI. Para chat, BigBlueButton cubre algunos casos de uso. Para recopilación de datos tipo survey, la actividad Feedback cubre muchos de los mismos escenarios.

### ¿Bootstrap 5 romperá mi tema personalizado?

Puede, dependiendo de cómo esté construido el tema. Moodle incluyó capas de compatibilidad para la transición de Bootstrap 4 a 5, pero no cubren todos los casos límite. Los temas personalizados que usen internos de Bootstrap 4 directamente deben probarse en un entorno de pruebas antes de producción.

### ¿Es obligatorio el nuevo subsistema de IA?

No. Las funcionalidades de IA de Moodle 5.0 son opcionales. Requieren configurar un proveedor y habilitarlas explícitamente. Un sitio sin proveedor de IA configurado no expone funcionalidades de IA a los usuarios.
